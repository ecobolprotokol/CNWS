Columnar Narrative Weight System (CNWS) adalah arsitektur penyimpanan dan eksekusi bobot model AI yang dirancang untuk mengatasi keterbatasan pendekatan model-weight tradisional pada penyimpanan, checkpointing, fine-tuning, selective loading, dan model evolution. CNWS tidak memperlakukan model sebagai satu kumpulan tensor besar yang harus disalin atau dimuat secara keseluruhan, melainkan memisahkan representasi model menjadi tiga lapisan utama: Column sebagai unit logis, Tile sebagai unit fisik, dan Pack sebagai unit persistence. Column merepresentasikan bagian bobot yang dapat dipilih, dikomposisikan, dan dikembangkan secara modular; Tile merupakan blok data berukuran hardware-friendly yang dioptimalkan untuk storage, memory transfer, cache, dan GPU compute; sedangkan Pack merupakan container immutable yang mengelompokkan Tile untuk penyimpanan lokal maupun distributed storage.

Pada level model, CNWS menggunakan Model Graph, Column Graph, dan Revision Graph untuk mendeskripsikan hubungan antara base model, tensor, Column Group, Tile, specialization, delta, dan versi model. "model.cnws" berfungsi sebagai manifest dan registry yang mereferensikan physical Pack tanpa menggandakan bobot. Setiap logical Column dapat dipetakan ke sejumlah physical Tile melalui Column Index dan Tile Index. Metadata dibagi menjadi hot metadata dan cold metadata; hot metadata berisi informasi yang diperlukan execution path seperti tensor ID, coordinates, offset, ukuran, dtype, encoding, dependency, dan revision, sedangkan cold metadata berisi narrative, provenance, lineage, domain, training context, dan informasi semantik lain yang tidak perlu dibaca pada hot path inference. Pemisahan ini menjaga fleksibilitas metadata CNWS tanpa menambahkan overhead pada runtime.

CNWS menggunakan Selector dan Execution Planner untuk mengubah kebutuhan model menjadi rencana eksekusi dan data movement. Selector menentukan Column atau Column Group yang relevan berdasarkan model revision, task, module, routing, atau execution context, kemudian Dependency Resolver memastikan seluruh dependency yang diperlukan tersedia. Execution Planner selanjutnya menerjemahkan logical Column menjadi physical Tile yang harus dibaca dan menentukan lokasi ideal setiap Tile berdasarkan kondisi hardware dan cache. Tile yang aktif dapat ditempatkan di VRAM, Tile yang akan segera digunakan dapat diprefetch ke RAM, sedangkan Tile yang dingin tetap berada di storage. Dengan demikian selective loading tidak sekadar berarti membaca sebagian file, tetapi melakukan selective computation dan selective data movement, sehingga CNWS dapat menghindari pembacaan dan materialisasi bobot yang tidak diperlukan.

Physical storage CNWS menggunakan immutable, content-addressed Column Data Pack yang dapat disimpan pada NVMe, filesystem lokal, maupun object storage. Tile yang identik dapat menggunakan hash yang sama sehingga beberapa model, specialization, atau revision tidak perlu menyimpan salinan fisik yang identik. Pack bersifat append-oriented dan tidak dimodifikasi setelah commit, sedangkan perubahan model direpresentasikan melalui Pack atau Tile baru yang direferensikan oleh Revision Graph. Atomic manifest commit, checksum, optional cryptographic signature, reachability analysis, dan garbage collection digunakan untuk menjaga crash consistency, integritas, reproducibility, dan pengelolaan storage jangka panjang. Pendekatan ini memungkinkan ribuan model turunan berbagi base weights dan physical tiles tanpa mengalami duplikasi penuh.

Untuk incremental checkpoint dan modular fine-tuning, CNWS menggunakan change-aware training pipeline. Setelah gradient dihitung, Change Analyzer mengidentifikasi Tile atau Column Group yang benar-benar mengalami perubahan dan mengklasifikasikan perubahan berdasarkan kepadatannya. Data yang tidak berubah tidak ditulis ulang, perubahan kecil disimpan sebagai Sparse Delta, perubahan menengah dapat menggunakan Hybrid Delta, sedangkan perubahan besar disimpan sebagai Dense Replacement Tile. Delta tidak dibiarkan membentuk rantai tanpa batas; CNWS menggunakan bounded delta depth dan asynchronous compaction untuk menggabungkan beberapa perubahan menjadi representation yang lebih efisien tanpa menghentikan execution runtime. Model baru kemudian direpresentasikan sebagai revision yang mengacu pada base weights ditambah changed Tiles, sehingga ukuran checkpoint secara ideal mendekati jumlah bobot yang benar-benar berubah, bukan ukuran keseluruhan model.

Pada runtime, CNWS menggunakan Tile Resolver, hierarchical cache, asynchronous I/O, prefetching, dan fused weight resolution untuk meminimalkan memory movement. Base Tile, Delta Tile, dan Adapter Tile tidak selalu harus digabung menjadi tensor baru sebelum digunakan; resolver dapat menyediakan representasi yang dapat diproses secara langsung oleh compute backend ketika format dan kernel mendukungnya. Data movement dilakukan secara pipeline sehingga storage read, decoding, host-memory transfer, GPU transfer, dan compute dapat berlangsung secara overlapping. Cache menggunakan informasi execution graph untuk menentukan Tile yang hot, warm, dan cold serta memprediksi Tile yang akan digunakan berikutnya, bukan hanya mengandalkan LRU sederhana. Tujuan utamanya adalah mengurangi read amplification, write amplification, memory amplification, unnecessary allocation, copy overhead, dan GPU stall tanpa mengorbankan layout Tile yang optimal untuk SIMD, tensor cores, dan accelerator-specific kernels.

CNWS diimplementasikan secara native dalam Rust dengan pemisahan modul "core", "physical", "graph", "planner", "storage", "cache", "resolve", "training", "runtime", dan "benchmark". Validasi performa tidak hanya menggunakan tokens-per-second, tetapi mengukur keseluruhan lifecycle model melalui storage size, deduplication ratio, read/write amplification, cache hit rate, VRAM/RAM amplification, planner latency, composition overhead, checkpoint latency, resume latency, GPU stall time, serta inference dan training throughput. Metric inti CNWS adalah Read Amplification = bytes read / bytes actually used, Write Amplification = bytes written / bytes effectively changed, dan Memory Amplification = memory occupied / weights actually required. Dengan kombinasi Column sebagai unit logical evolution, Tile sebagai unit physical performance, dan Pack sebagai unit persistence, CNWS ditujukan menjadi sistem weight storage, incremental model evolution, modular composition, selective execution, dan hardware-aware runtime dalam satu arsitektur yang scalable, bukan sekadar format file bobot baru.
